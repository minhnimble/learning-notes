# Getting Started with AWS

## AWS Cloud Overview - Regions & AZ

### 1. History of AWS
- **Launched**: 2002, initially for internal use at Amazon.
- **Public Services Start**: 2004 with SQS, followed by S3 and EC2 in 2006.
- **Market Position**: As of Q1 2024, AWS has $90 billion in revenue and a 31% market share.

### 2. Global Infrastructure
- **Regions**: AWS has multiple regions worldwide, including in Europe, Asia, and South America.
- **Availability Zones**: Each region contains several isolated data centers to prevent cascading failures.

### 3. Choosing Regions
- **Factors to Consider**: Compliance, latency, service availability, and pricing.

### 4. Points of Presence
- Introduction of edge locations to improve content delivery by minimizing latency.

### 5. AWS Services
- Overview of region-scoped and global services to be explored further in the course.

## Tour of the AWS Console & Services in AWS

### 1. AWS Console Home
- **Introduction**: Overview of the console, highlighting the regions selector in the top right corner to optimize latency by selecting a geographically closer region.

### 2. Console Layout
- **Design Overview**: Features a list of recently visited services, sections dedicated to AWS health, usage metrics, and tutorial access.

### 3. Navigating Services
- **Service Browsing**: Users can explore services alphabetically or by category. The search bar enables quick access to specific services, such as Route 53.

### 4. Service Specifics
- **Regional vs Global Services**: Some services, like Route 53, are global (no regional selection needed), whereas services like EC2 are region-dependent.

### 5. Course Region Consistency
- **Importance**: Emphasizes the need to remain within the same region throughout the course due to differing resource availability.

### 6. AWS Global Infrastructure
- **Service Availability**: Encourages users to check regional service availability information, especially if they encounter any issues during the course.
